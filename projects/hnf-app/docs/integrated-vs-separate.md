# 통합 앱 1개 vs 별도 앱 2개 — 비교 분석

여드름 관리와 탈모 관리를 **하나의 통합 앱**으로 만들지, **별도 앱 2개**로 만들지에 대한 비교입니다.

## 결론 요약

**통합 앱 1개 + 내부는 "관심사 모듈" 구조를 권장합니다.**
단, 모듈 경계를 명확히 유지해 나중에 별도 앱으로 분리할 수 있는 길을 열어둡니다. (이 저장소의 `projects/hnf-app/`이 그 구조입니다.)

## 기능 관점: 코드의 90%가 공유됨

선정한 4개 핵심 기능은 여드름/탈모 모두 **동작 방식이 완전히 동일**하고, 콘텐츠(도메인)만 다릅니다.

| 기능 | 여드름 | 탈모 | 공유 여부 |
|------|--------|------|-----------|
| 사진 기록/타임랩스 | 얼굴 정면·좌우 | 정수리·헤어라인 | 엔진 100% 공유 (촬영 가이드 문구만 다름) |
| 루틴 체크리스트 | 세안·스팟케어 | 샴푸·마사지·약 | 엔진 100% 공유 (템플릿만 다름) |
| AI 사진 분석 | 트러블 개수/홍조 | 모발 밀도/두피 상태 | 인터페이스 공유 (분석 모델만 교체) |
| 제품/성분 추천 | 성분 필터링 | 성분 필터링 | 엔진 100% 공유 (데이터만 다름) |

## 항목별 비교

| 항목 | 통합 앱 1개 | 별도 앱 2개 |
|------|-------------|-------------|
| 개발·유지보수 | 코드베이스 1개, 수정 1회 | 공통 수정도 2회 반복 (또는 모노레포 관리 부담) |
| 앱스토어 운영 | 심사·업데이트·리뷰 관리 1건 | 모두 2배 |
| EAS 빌드 할당량 (Free: 월 15회/플랫폼) | 앱 1개 기준으로 여유 | 앱 2개가 할당량을 나눠 씀 |
| ASO(스토어 검색) | "여드름", "탈모" 키워드가 한 앱에 섞여 각각의 검색 순위에는 불리 | 각 앱이 키워드에 집중, 검색 노출 유리 |
| 브랜드 명확성 | "피부·두피 케어"로 포지셔닝 필요 | "여드름 앱", "탈모 앱"으로 명확 |
| 20대 타겟 적합성 | 여드름+탈모 동시 고민층을 한 앱에서 흡수(교차 활용) | 두 앱을 각각 설치해야 함 |
| 30~50대 확장 | 모듈 추가만으로 확장 (주름, 모공, 두피 노화 등) | 세 번째, 네 번째 앱이 필요해질 수 있음 |
| 데이터 자산 | 한 사용자의 피부+두피 기록이 한 곳에 쌓임 → 연령 전환기 추천에 유리 | 사용자 데이터가 분산됨 |

## 판단 기준

- **1인/소규모 팀 + MVP 검증 단계**라면 통합 앱이 명확히 유리합니다. 운영 부담이 절반이고, 어떤 도메인(여드름 vs 탈모)이 더 반응이 좋은지 한 앱 안에서 데이터로 확인할 수 있습니다.
- 별도 앱의 실익(ASO 키워드 집중)은 **마케팅에 투자할 단계**에서 의미가 커집니다. 그 시점이 오면 검증된 도메인 모듈만 떼어 전용 앱을 추가 출시하면 됩니다(통합 앱은 유지).

## 분리를 쉽게 만드는 설계 (이 스캐폴딩에 적용됨)

1. **도메인 콘텐츠와 엔진의 분리**: `src/core/`(엔진)는 `ConcernType` 문자열만 알고, `src/modules/`(도메인)가 라벨·루틴 템플릿·촬영 가이드를 제공
2. **레지스트리 패턴**: `src/modules/registry.ts`에 등록된 모듈 배열이 온보딩 선택지와 기능 활성화를 결정 → 전용 앱을 만들 땐 레지스트리에 모듈 1개만 남기면 됨
3. **데이터에 concern 태그**: 사진·루틴·제품·가이드 데이터가 모두 `concern` 필드를 가져 필터링만으로 도메인이 분리됨

## 연령대 확장 전략

온보딩에서 수집한 연령대(`AgeGroup`)가 추천·가이드 필터의 축이 됩니다.

- 20대: 여드름 + 초기 탈모 예방 (현재 모듈로 커버)
- 30대: 성인 여드름 + 본격 탈모 치료 안내 (현재 모듈 + 콘텐츠 보강)
- 40~50대 이상: 피부 장벽·주름, 모발 밀도 유지 → **신규 모듈**(`wrinkle`, `scalp-aging`)을 registry에 추가
